The benchmark

The Vulpine Control Architecture Benchmark.

Eleven areas of control, seventy-one requirements, and one question: how much authority is this agent allowed to hold, and what has to be true before it holds it. Published in full so a client can check our work, and so a bank can hand it to an examiner.

What it is

A control model, not a maturity survey.

VCA stands for Vulpine Control Architecture. Every requirement in it carries an identifier like VCA-4, so a finding in an assessment report, a slide in a board pack and a line in a remediation plan can all point at the same thing.

It exists because the usual question, "is this model safe", cannot be answered. The question it replaces is answerable: what can this agent actually do, what stops it doing more, and can you prove the stop works. That reframing is the whole method.

The benchmark is vendor-neutral. It says nothing about which model, cloud or framework a client runs. It is reviewed every quarter and whenever a framework it maps to changes.

How each area is scored

Four levels, and the score is the weakest link.

A domain scores at its weakest requirement, never the average. A control that works for nine paths out of ten is not a control.

An agent gets more authority by earning it, one level at a time.

The eleven domains

All eleven, in full.

Six of them carry a higher bar. Those six have to be independently proven, not just switched on, before an agent is allowed to do something that cannot be undone. The other five have to be enforced, which is a real requirement but a lower one. Both are marked below.

What the levels buy

Authority is granted by tier, and every tier has a gate.

A workflow's tier is the tier of its most consequential step. An agent that can cause a T3 action indirectly, by asking another agent, is treated as holding T3 authority itself.
