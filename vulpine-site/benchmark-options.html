Three ways to show the benchmark.

All three render from the same data module, so none of the numbers are hand-typed. The problem with the built version is not the styling — it is that the gating rule defines a required maturity level for every domain at every tier, and the page prints a count instead.

E

Spec table — the recommendation

Modelled on the Tailscale pricing comparison, mirrored and rendered. Every row is a name with a small grey descriptor beneath it, and the tier columns carry plain text values rather than graphics. That is the fix for the real problem: the domain descriptors already exist in the data and the built table has nowhere to put them, so eleven domains arrive as eleven names a reader cannot evaluate. Hairlines, generous row height, no card, no heavy border.

Reference · Tailscale pricing comparison — feature name with a grey sub-caption, tier columns carrying a literal value or an en dash, quiet hairline rows.
Not copied: Tailscale groups its rows into named sections. The benchmark defines eleven domains and no groups, so inventing groupings would be making something up.

D

Tier-led

Rendered the CIS Navigator rather than reading its markup, and it does not put the Implementation Groups in a column — IG1/IG2/IG3 are the primary control at the top of the page, and the standard reflows to show what the selected group demands. Applied here, the reader picks the authority they need to grant and the instrument answers “then this is what you must clear.” That is the sales argument, not an inventory. The four-segment meter is the ASVS idea: publish the level shape, never a bare count.

Reference · CIS Controls Navigator — IG1/IG2/IG3 as the top-level filter; each control a panel with its name left and “5/5 Safeguards” right.
Reference · MITRE ATT&CK Enterprise Matrix — item count set directly under the column heading. Worth noting the base matrix carries no tiers at all; scoring is a separate Navigator overlay, so it is the wrong model for a gating story.
T3 is rendered into the markup, so with JavaScript off the panel shows the hardest gate instead of going blank.

A

The gate matrix

Domains down, authority tiers across; the cell is the maturity level that tier demands. You can see the argument in one look: T2 is a flat bar across all eleven, and T3 is where six of them step up. Orange appears only on that step, so the accent still marks a decision rather than magnitude.

Reference · CIS Critical Security Controls v8.1 Navigator — controls down, nested Implementation Groups across.
Reference · OWASP ASVS 5.0 — 17 chapters, 345 requirements, published as a per-chapter level distribution rather than a bare count.

B

Control cards

Each domain is a unit: identifier, name, one line of what it actually means, its requirement count, and a three-step ramp. The descriptor finally has somewhere to live — the table has nowhere to put it, so eleven domains currently arrive as eleven names a reader cannot evaluate. Degrades to one column on a phone without a separate mobile component.

Reference · CIS Controls Navigator card pattern — control number, safeguard count, Implementation Group tags per control.

C

The current list, with the ramp added

The smallest change from what is already built. Same rhythm, same restraint, but the gate column becomes a three-segment ramp instead of the string "T2 · T3". Lowest risk if you like the current density and only want the shape to read at a glance.

Reference · ASVS per-chapter level bars.

My recommendation is E. It carries the descriptors, which is the actual defect — without them eleven domains are eleven names a reader cannot evaluate — and it shows the whole gating rule without asking anyone to click. D is the better answer if the instrument should ask a question rather than publish a spec. A, B and C are earlier passes, kept for comparison.

On the references: CIS and MITRE are structurally the closest published control frameworks, but they are not sites worth imitating visually. Tailscale's comparison solves the same problem and is designed properly, so E takes its mechanics — name plus grey descriptor, tier columns carrying literal values, quiet hairline rows.
